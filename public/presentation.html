Foundational Operating Systems Theory

Dijkstra's 3 Classical Critical Section Requirements

Any valid concurrency control mechanism must mathematically satisfy all three properties:

01

Mutual Exclusion

Only one process or execution context may execute inside the critical section at any given millisecond. If Process A is inside, Process B is blocked.

02

Progress

If no process is currently in the critical section and some wish to enter, selection cannot be postponed indefinitely. Deadlock is strictly forbidden.

03

Bounded Waiting

A bound must exist on the number of times others enter before a granted request. Our FIFO queue eliminates thread starvation entirely.

Source Code Walkthrough

Our Promise-Based FIFO Mutex Implementation

src/core/Mutex.js — acquire(threadId) 
acquire(threadId) {
  if (!this._locked) {
    // Fast Path: Lock is completely free
    this._locked = true;
    this._currentOwner = threadId;
    return Promise.resolve(() => this._release(threadId));
  }

  // Contention Path: Lock held — enqueue for Bounded Waiting (FIFO)
  this.metrics.totalContentions++;
  return new Promise((resolve) => {
    this._queue.push({
      threadId,
      grant: () => {
        this._locked = true;
        this._currentOwner = threadId;
        resolve(() => this._release(threadId));
      }
    });
  });
}

When release() is invoked, it pops the next waiter from the FIFO queue in strict arrival order — guaranteeing zero starvation.

Engineering Takeaways

Key Insights for Concurrent Systems Design

1. The Async Illusion

Node.js is single-threaded on CPU, but async I/O interleaves requests during await delays. Without synchronization primitives, async apps suffer the exact same race hazards as multithreaded C systems.

2. Lock Granularity Balance

Coarse locks create throughput choke points; overly fine locks invite deadlocks. Per-resource keyed mutex registries provide the golden balance between throughput and isolation.

3. Starvation Elimination

A simple boolean lock flag or randomized retry can leave unlucky threads starving forever. Explicit FIFO queues guarantee bounded waiting and predictability.

4. Observability & Crash Recovery

Every critical section entry and release must be audit-logged. In-memory locks release cleanly on process restart, while data commits are preserved via atomic disk flushes.
